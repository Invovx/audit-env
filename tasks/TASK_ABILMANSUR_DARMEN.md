Проект: RL-среда для ИИ-аудитора (Genesis FinTech). Код: `schemas.py`, `generator.py`, `env.py`,
`evaluator.py`, `baselines.py`, `check.py`, `tests/`. Сейчас `python check.py` → ALL CHECKS PASSED

Правила: Python 3.11, только стандартная библиотека; деньги — `int` в минимальных единицах;
курсы — `Decimal`; всё детерминировано от `(seed, config)`; эталон и ход генерации — только в
`truth`/`provenance`; в публичных файлах нет слов и тегов, подсказывающих ошибку.

Уже сделано (версия 1.1): книга в базовой валюте (класс `Translator`), ошибки
`duplicate_invoice`, `period_cutoff_error`, `partial_payment_allocation` (смотрите его как

Как добавлять ошибку: подкласс `Mutator` + запись в `MUTATORS` + константа в `schemas.py`
(и в `ALL_ISSUE_TYPES`) + описание в `TASK_DESCRIPTION` (`env.py`) + ветка в тесте
`_truth_is_semantically_true` (`tests/test_core.py`). Мутатор меняет историю одним причинным
изменением; книга остаётся сбалансированной (генератор проверяет это сам после ошибок).

## Задача 1: `fx_rate_error`

У `Translator` есть `rate_overrides`: `books.translator.rate_overrides[(id(record), "booking")] = "<курс>"`
подменяет курс, по которому проведён счёт (`"cash"` — курс платежа). Сделайте мутатор:
- берёт счёт в иностранной валюте (зарезервируйте такие истории через `reserved_specs`) и проводит
  его по курсу НЕ той даты: дата срока оплаты, следующий рабочий день или курс на выходные взят
  не по правилу (`policy.fx_rate_date_rule`);
- курс подмены должен реально отличаться (иначе выберите другой);
- сумма в эталоне = |неверная сумма − верная сумма| в базовой валюте, валюта = базовая;
- доказательства: документ счёта + строка дебиторки (или выручки) + строка `fx.csv` с правильным
  курсом (ID вида `FX-2026-01-15-USD-KZT`);
- отвлекающий случай уже есть: выходные, где законно берётся курс пятницы. Проверьте, что
  он не похож на ошибку.

## Задача 2: два сценария взаимодействующих ошибок

1. Частичный платёж в иностранной валюте на границе периода (пример из условия).
2. Счёт с датой следующего периода проведён в текущем **и** по курсу не той даты.

Каждая ошибка в сценарии — отдельная запись эталона, каждая доказуема сама по себе. Добавьте в
`EpisodeConfig` поле `interactions` (список сценариев), чтобы их можно было включать/выключать.
