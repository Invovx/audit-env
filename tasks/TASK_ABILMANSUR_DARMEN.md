# Задание: Абильмансур и Дармен (вставьте этот файл целиком своему ИИ вместе с кодом проекта)

Проект: RL-среда для ИИ-аудитора (Genesis FinTech). Код: `schemas.py`, `generator.py`, `env.py`,
`evaluator.py`, `baselines.py`, `check.py`, `tests/`. Сейчас `python check.py` → ALL CHECKS PASSED.
Это нельзя сломать.

Правила: Python 3.11, только стандартная библиотека; деньги — `int` в минимальных единицах;
курсы — `Decimal`; всё детерминировано от `(seed, config)`; эталон и ход генерации — только в
`truth`/`provenance`; в публичных файлах нет слов и тегов, подсказывающих ошибку.

Как добавлять ошибку: в `generator.py` есть класс `Mutator` и два примера (`DuplicateInvoice`,
`PeriodCutoffError`). Новый тип = новый подкласс + запись в `MUTATORS` + константа в `schemas.py`
+ тип в `EpisodeConfig.error_types` по умолчанию + описание в `TASK_DESCRIPTION` (`env.py`).
Мутатор меняет чистую историю **одним причинным изменением**, книга остаётся сбалансированной,
в `Issue` указаны затронутые ID, точная сумма расхождения, валюта и наборы доказательств,
которые агент реально может получить инструментами.

## Задача 1 (начинайте сразу): `partial_payment_allocation`

Платёж пришёл (документ и проводка кассы на полную сумму), но в книге он привязан к счёту
не полностью или совсем не привязан; остаток уходит на новый счёт `2100 Unapplied cash`.
- Варианты: «частично» и «не привязан» (у строки дебиторки `invoice_id` = null).
- Сумма в эталоне = непривязанная сумма; доказательства: документ платежа + строка кассы +
  строка 2100 (или строка дебиторки).
- Отвлекающий случай, который НЕ ошибка: законный платёж частями (уже есть) — убедитесь,
  что он не похож на ошибку по тем же признакам.

## Задача 2 (после того как Санжар сделает пересчёт валют): `fx_rate_error`

Проводка по документу в иностранной валюте пересчитана по курсу не той даты (например, дата
срока оплаты, предыдущий день или курс выходного взят неправильно). Сумма в эталоне = разница
в базовой валюте; доказательства: документ + проводка + строка `fx.csv` с правильным курсом.
Отвлекающий случай: выходной день, где по правилу законно берётся курс пятницы.

## Задача 3: два сценария взаимодействующих ошибок

1. Частичный платёж в другой валюте на границе периода (пример из условия).
2. Например: счёт с датой следующего периода проведён в текущем **и** по курсу не той даты.

Каждая ошибка в сценарии — отдельная запись эталона, каждая доказуема сама по себе; конфиг
позволяет включать/выключать сценарии (`interactions` в `EpisodeConfig`).

## Задача 4: сделать среду сложнее

Сейчас простая сверка из `baselines.py` находит 100% ошибок. Цель: она должна находить
явно меньше (например F1 0.4–0.7), а oracle — по-прежнему 1.0. Добавьте похожие на ошибки,
но законные случаи и ошибки, которые требуют пересчёта.

## Тесты (обязательно для каждого типа)

- книга сбалансирована до и после ошибки, расхождение ровно равно сумме в эталоне;
- доказательства существуют и достаточны (пересчёт по записям, а не по эталону);
- на чистых книгах эталон пуст, отвлекающие случаи присутствуют;
- обновите `configs/train.json` и `configs/dev.json`, чтобы новые типы и сценарии там были.
