# Записка о дизайне AuditEnv

> Версия 1.1 (генератор 1.1.0). Разделы с пометкой **[обновить]** дополняются по мере работы.

## 1. Идея

Эпизод — одна вымышленная компания и один отчётный период. Агент исследует записи
через узкий набор инструментов и отправляет выводы с доказательствами. Среда не
обучает модель; она даёт повторяемые взаимодействия и честную терминальную награду.

## 2. Генерация: сначала история, потом ошибки

1. **План.** По seed решается, какие ошибки и сколько будет внесено.
2. **Чистая история.** Контрагенты, счета, кредит-ноты, платежи (полные, частями, сразу за
   несколько счетов), регулярные счета на одинаковую сумму, документы на границах периода,
   операционные проводки, таблица курсов FX.
3. **Проверка чистых книг.** Дебет = кредит в каждой валюте, дебиторка по проводкам сходится
   с документами, ни один счёт не переоплачен. Результат пишется в `provenance.clean_books_checks`.
4. **Мутации.** Каждый тип ошибки — отдельный `Mutator`, который меняет историю одним
   причинным изменением и записывает, что изменено (`provenance.mutations`).
5. **Финализация.** Из записей выводится книга проводок, назначаются ID, формируются публичные
   файлы, `truth.json` (тип, затронутые ID, сумма, валюта, допустимые наборы доказательств) и
   `provenance.json`. Эталон ссылается на объекты, а не на номера строк, поэтому переживает
   переименование и перестановку.

Порядок этапов: история → курсы → проверка чистых книг → ошибки → операционные проводки,
которые добирают книгу ровно до `n_ledger_rows` (поэтому ошибка может менять число строк) →
повторная проверка баланса и сверки дебиторки после ошибок.

**Валюты.** Книга ведётся в базовой валюте, документы — в своей. Счёт пересчитывается по курсу
локальной даты проводки (выходные → последний более ранний курс), касса — по курсу даты платежа,
погашение дебиторки и кредит-ноты — по историческому курсу счёта; полное погашение снимает ровно
остаток, без копеек хвоста; разница идёт на 4900. Правила опубликованы в `policy.json`, тесты
пересчитывают каждую проводку только по публичным файлам (`tests/test_fx.py`).

Детерминизм: собственный ГПСЧ SplitMix64 с отдельными подпотоками на каждый этап, деньги —
целые минимальные единицы, курсы — десятичные строки, `Decimal` с `ROUND_HALF_UP`.

## 4. Отвлекающие случаи (не ошибки)

Платёж частями, один платёж на два счёта, переплата (остаток законно лежит в 2100), возврат через кредит-ноту, одинаковые суммы
каждый месяц, документы ровно на начале и конце периода, время в UTC, которое выглядит как
другой день, документы вне периода без проводок.

## 5. Изоляция

- Среда хранит только публичные таблицы; эталон лежит внутри `Evaluator`.
- `evaluator.py` импортирует только стандартную библиотеку и `schemas` (проверяется тестом).
- Наблюдения и `info` не содержат seed, путей, ID эталона; сообщения об ошибках ≤ 200 символов.
- В режиме `eval` награда и диагностика не возвращаются политике.
- **[обновить]** Сейчас оценщик живёт в том же Python-процессе; в работе запускатель, где агент
  общается со средой только через JSON, а оценщик находится в другом процессе.

## 6. Сопоставление и награда

- Выводы канонизируются: списки ID сортируются, повторы ID внутри списка удаляются.
- TP: совпадают тип, `affected_ids`, валюта, сумма в пределах `amount_tolerance_minor`
  (из `policy.json`) и есть хотя бы один полный допустимый набор доказательств; лишние ID
  в доказательствах не мешают.
- Сопоставление взаимно однозначное и максимальное (augmenting paths), поэтому порядок выводов
  не влияет на результат; повторный вывод — FP.
- P, R, F1 и особые случаи пустого эталона — ровно по условию; награда
  `clip(2*F1 - 1 - 0.002*inspection_steps, -1, 1)`; неверная структура → −1 с записью в журнал.

## 7. Измерения базовых политик  **[обновить]**

10 train + 10 dev эпизодов, из них по 2 чистых в каждом сплите (`python check.py`):

| Политика | F1 train / dev | Возврат train / dev | Шаги | с/эпизод |
|---|---|---|---|---|
| случайный исследователь | 0.10 / 0.10 | −0.80 / −0.80 | 14 | 0.02 |
| простая сверка | 0.62 / 0.79 | 0.21 / 0.55 | 18 | 0.02 |
| «пометить всё» | 0.00 / 0.00 | −1.00 / −1.00 | 1.5 | 0.02 |
| oracle | 1.00 / 1.00 | 1.00 / 1.00 | 0 | 0.02 |

**Разбор сбоев.** В версии 1.0 (2 типа ошибок) простая сверка получала F1 = 1.00: среда была
слишком лёгкой. В 1.1 добавлены пересчёт валют, частичное распределение платежа и законная
переплата. Простая сверка ошибается в двух местах: принимает переплату за ошибку (FP) и указывает
сумму в базовой валюте вместо валюты платежа (FN на иностранных платежах).

## 8. Честные ограничения  **[обновить]**

- Реализованы 3 типа ошибок из 4 (нет ошибки курса); сценарии взаимодействия ещё не готовы.
- ID пока назначаются последовательно; схема со случайными ID и перестановкой — в работе.
- Высокая награда в этой среде не доказывает пригодность модели для реального аудита.
- Обучение весов не проводилось; заявлений об улучшении модели нет.
